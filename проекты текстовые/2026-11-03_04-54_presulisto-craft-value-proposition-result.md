### §1. Сегмент и бизнес-контекст

Причинные признаки — гипотезы:

- Повторяемость позволяет переиспользовать содержание, а не исследовать объект заново.

Размер 2–10 мастеров — вспомогательный признак из исследования. Знакомство с основателем — канал, не сегмент. Наличие S2 и его недовольство существующим способом не доказаны.

### §2. Задача, восемь элементов и критерии

Формулировка составлена моделью, **не является цитатой клиента**:

«Когда постоянный заказчик просит расчёт знакомых работ, хочу получить редактируемый черновик повторной сметы по своим утверждённым позициям и ценам, без неподтверждённых добавлений и с меньшим полным трудом, чтобы согласовать выполнимый прибыльный заказ».

| Элемент задачи | Содержание и статус |
|---|---|
| Контекст | Знакомые работы; есть свои одобренные позиции; владелец составляет и проверяет — унаследованная гипотеза |
| Отрицательные эмоции | Раздражение от переписывания, опасение ошибки — гипотеза, не наблюдение |
| Известные способы | Шаблон, Excel/Word, WhatsApp, человек; фактический набор выбора конкретного владельца неизвестен |
| Триггер | Запрос постоянного заказчика на знакомый объём — гипотеза |
| Ожидаемый результат | Получить редактируемый черновик повторной сметы |
| Критерии | Таблица ниже; численные клиентские пороги неизвестны |
| Большая задача | Согласовать выполнимый прибыльный заказ; лично — избежать ошибки и стыда перед постоянным заказчиком |
| Желаемые эмоции | Контроль, спокойствие после проверки — гипотеза |

Частота 4–12 подходящих смет/месяц и бюджет задачи €1 200–4 800/год — унаследованные сценарии для проверки, не наблюдённые показатели. Важность численно не измерена.

| Критерий | Уровень приемлемости и измерение | Затрата / предполагаемый порядок | Связь с большой задачей |
|---|---|---|---|
| Свои цены | Каждая использованная цена соответствует утверждённому основанию либо отдельно решена владельцем | Контроль, умственный труд; №1 | Не согласовать заказ на чужой цене |
| Полнота | Предоставленные владельцем позиции не потеряны; неподтверждённое выделено | Надёжность, тревога; №2 | Не пропустить согласуемую работу |
| Повторный ввод | Уже предоставленные позиции и цены не набираются заново | Усилие, лишние действия; №3 | Сократить подготовительную работу |
| Полный труд | Сумма всех шагов меньше привычного способа при пригодном результате | Время, усилие; точный приоритет не измерен | Сохранить время владельца |
| Пригодность | Редактируемый черновик можно проверить и использовать для предложения | Надёжность; минимальное условие | Продвинуться к согласованию |
| Допустимые данные | Конкретный поток соответствует ограничениям и отдельной квалифицированной проверке | Объективное ограничение | Сделать путь исполнимым |

У всех клиентских критериев статус гипотезы. Рабочая комбинация: контроль + надёжность, затем снижение труда. Ведущие механики: лучше выполнить критерии контроля, убрать повторное переписывание, снизить затраты до результата. Нельзя компенсировать неподтверждённую цену скоростью.

<a id="section-3"></a>
### §3. Предполагаемые затруднения и выгоды

Затруднения, в рабочем порядке: риск неподтверждённой цены; потеря позиции при копировании; повторный набор; очистка старого документа; обезличивание и дополнительная проверка нового инструмента. Ни частоты, ни сила 1–10 не измерены.

Предполагаемые выгоды: прослеживаемые свои цены; видимое неизвестное; меньше повторного набора; пригодный после проверки черновик; меньше полного труда. Нет утверждения, что текущие альтернативы систематически нарушают эти критерии.

<a id="section-4"></a>
### §4. Граф задач и переход до → после

Граф и цепочка — гипотезы. Основная задача продукта выше узлов J1–J8; согласование прибыльного заказа находится выше продукта. Документирование изменений действующего заказа — соседняя отложенная задача.

| Узел | Когда и какой результат нужен | Критерий и назначение | Возможный разрыв |
|---|---|---|---|
| J1 Уточнить объём | После запроса получить достаточный перечень знакомых работ | Не подменить текущий объём прошлым; основание черновика | Неполный ответ заказчика |
| J2 Найти основание | Перед расчётом выбрать свои подходящие позиции | Одобренные, актуальные для случая | Нет подходящего образца |
| J3 Подготовить допустимый ввод | До обработки получить обезличенный полезный текст | Ограничения соблюдены, смысл сохранён | Обезличивание дорого или недостаточно |
| J4 Выбрать состав | По объёму отобрать нужные позиции | Ничего указанного не потеряно, лишнее не добавлено | Похожие названия скрывают разные работы |
| J5 Задать значения | Для позиций указать объёмы и утверждённые цены | Не угадывать неизвестное | Нет единицы, цены или решения |
| J6 Получить черновик | После решений собрать редактируемый документ | Содержание не искажено | Ошибка переноса или арифметики |
| J7 Проверить результат | До использования сверить состав, цены и неизвестное | Владелец может принять обоснованное решение | Проверка съедает выигрыш |
| J8 Передать документ | После проверки подготовить предложение к согласованию | Передаётся проверенная версия | Потери при переносе формата |

Для каждого узла «зачем» — получить проверяемый черновик текущей повторной сметы; J8 связывает его с согласованием заказа. Рассмотрены раздражение, тревога и знание привычного шаблона; их конкретные проявления и исходные ожидания не наблюдались.

Временная проекция: J1 → J2 → J3 → J4 → J5 → J6 → J7 → J8. Подготовка утверждённого набора — отдельная предварительная затрата, не спрятанная за цепочкой повторного использования. Заказчик → владелец в J1 — внешняя передача; владелец → средство обработки в J3 — граница данных. Возможный цикл: J7 → J4/J5 → J6 → J7. Длительности неизвестны.

| Измерение | Привычный путь — гипотеза | A — проектируемый путь |
|---|---|---|
| Получение черновика | Скопировать образец, очистить, переписать | Выбрать утверждённое, указать изменения, собрать |
| Что остаётся владельцу | Уточнение, цены, объёмы, проверка, отправка | Те же решения и окончательная проверка |
| Что предполагаем убрать | — | Повторный набор уже утверждённых данных |
| Новые затраты | — | Подготовка набора, актуализация, обезличивание, освоение |
| Результат | Время и ошибки неизвестны | Выигрыш не измерен |

Окупаемость настройки: `число повторений = труд настройки / экономия на повторении`, только если экономия положительна. Приемлемый клиенту горизонт неизвестен — выяснить на прошлых случаях, не придумать. Малые выборки не дают долю успеха рынка или статистическую достоверность.

<a id="glossary"></a>
**Словарь**

- Задача / Job — желаемый результат в конкретной ситуации и условиях успеха.
- Основная задача / Core Job — законченный результат в границах продукта.
- Большая задача / Big Job — более широкий результат, которому продукт помогает.
- Граф задач — отношения задач разных уровней; цепочка — их необходимая последовательность во времени.
- Механика — конкретный способ увеличить результат или уменьшить затраты.
- Aha — замеченный клиентом результат лучше ожидания, не факт появления текста.
- RICE — условное сравнение применимости, эффекта, доказательности и труда.
- RAT — дешёвая проверка самых опасных предположений.
- CAC — стоимость привлечения покупателя; LTV — вклад за срок его жизни.
- Валовая маржа — доля выручки после прямых расходов, до общих затрат.
- Primary / supplementary — выбранное основное / отдельное дополнительное направление.
- PRD — документ требований к продукту; этот отчёт передаёт ему гипотезу ценности и ограничения.
- GATE — проверка условий перехода; учебное разрешение продолжить не меняет её результата.
